# Database migrations

PGCC uses Alembic for versioned schema changes. Do not run destructive migrations against production without a verified backup and review.

## Commands (from backend/)

- `alembic current` — inspect migration revision.
- `alembic revision --autogenerate -m "describe change"` — generate a candidate migration; review it manually.
- `alembic upgrade head` — apply migrations.
- `alembic downgrade -1` — roll back one revision only after reviewing the downgrade and verifying backup/recovery procedures.

## Baseline policy

The existing project has historically initialized schemas with SQLAlchemy `create_all`. Before adopting Alembic in an existing deployment, inspect the actual database schema and data, back it up, and establish a reviewed baseline revision. Do not blindly apply an autogenerated initial migration to an existing database. The migration environment imports all models so metadata is complete.
